# Требования к AI-агенту бронирования

Решили добавить LLM-агента поверх текущего REST API. Суть: дать пользователям возможность не тыкать фильтры, а просто написать "хочу поиграть в пятницу".
Накидывал эти требования изначально у себя в Obsidian, сейчас переношу сюда набело.

## 1. Доступные инструменты (Function Calling / Tool Calling)

Агент ходит в те же методы, что и фронт. Никаких бэкдоров и прямых походов в БД.

### Tool 1: `find_available_slots`
Маппинг на: `GET /fields/available-slots`
**JSON Schema для LLM:**
```json
{
  "name": "find_available_slots",
  "description": "Поиск свободных слотов для игры. Использовать, когда пользователь ищет поле.",
  "parameters": {
    "type": "object",
    "properties": {
      "date": { "type": "string", "description": "Дата в формате YYYY-MM-DD" },
      "fieldType": { "type": "string", "enum": ["5x5", "8x8", "11x11"] },
      "timeFrom": { "type": "string", "description": "Время от (HH:MM)" },
      "timeTo": { "type": "string", "description": "Время до (HH:MM)" }
    },
    "required": ["date"]
  }
}
```
*Открытый вопрос:* `complexId` пока убрал из required для агента, пусть ищет по всем комплексам, если юзер явно не уточнил. Завел CR смежникам, чтобы сделали этот параметр опциональным на бэке.

### Tool 2: `create_booking`
Маппинг на: `POST /bookings` (нужен slotId, fieldType и userId).

## 2. Алгоритм работы и Edge Cases

- **Слот уже занят (Race condition):** Юзер долго думал в чате, и при вызове `create_booking` падает 409 Conflict.
  *Поведение агента:* Извиниться, сказать "пока мы общались, слот ушел", и автоматически вызвать `find_available_slots` на то же время, чтобы сразу предложить замену. Не заставлять писать запрос заново.
- **Неполный контекст:** Если юзер пишет "забронируй поле", агент НЕ должен подставлять сегодняшнюю дату от себя. Должен триггериться фоллбэк: "На какую дату и время ищем?"
- **Переключение контекста:** Юзер искал поле, а потом резко пишет "а какие у вас вообще правила отмены?". Агент должен ответить на вопрос (RAG по базе знаний) и мягко вернуть в русло: "Вернемся к бронированию на пятницу?"
